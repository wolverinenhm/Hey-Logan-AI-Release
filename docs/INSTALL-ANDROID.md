# Installing Hey Logan AI on Android

The Android app is a **companion** for the PC app: the assistant itself runs on
your Windows PC, and the phone is your microphone, screen and speaker for it.
Both devices must be on the same Wi-Fi network, and **the PC app must be
running** while you use the phone.

## Requirements

- Android 8.0 (API 26) or newer, with a browser/WebView (any modern phone).
- The PC running Hey Logan AI, reachable on your local network.
- Microphone permission (for voice) — the app asks on first use.

## 1. Install the APK

Copy **`HeyLoganAI-android-1.0.0.apk`** to the phone (USB cable, a cloud drive,
or email it to yourself) and tap it in the phone's Files app.

Android will ask to allow installing from that app the first time:
**Settings → Install unknown apps → allow** for Files/Drive/Chrome, then confirm.

With USB debugging enabled you can also install it from the PC:

```
adb install -r HeyLoganAI-android-1.0.0.apk
```

The APK is signed with a release key, so it installs and updates normally; it
is not distributed through Google Play.

## 2. Pair the app with your PC

1. On the PC: Start Menu → **Hey Logan AI → Pairing**. It shows:
   - your **access token** (e.g. `WEQ5-89Y8-P4ED`),
   - the **LAN address** (e.g. `https://192.168.0.104:8443`),
   - **pairing links** that already include the token,
   - a **QR code**.
2. Open **Hey Logan AI** on the phone. On the connect screen you can:
   - type the **address** (e.g. `192.168.0.104:8443`) and the **token**, or
   - paste the whole **pairing link** (it fills in both fields).

   The app does not need a camera: a 14-character token is quick to type, and
   the pairing link can be sent to the phone with any messenger or notes app.
3. Tap **Connect**.

The app remembers the PC, so next time it opens straight into the assistant.

> **About the certificate warning:** the PC serves HTTPS with a certificate it
> generated itself, so your phone/WebView does not recognise it. The app
> explains this once and then trusts *only your PC's address* — other
> certificates are rejected. It is safe to continue: the traffic never leaves
> your network.

## 3. Use it

1. Tap the orb / **Start listening**.
2. Say a wake phrase:
   - **"Hey Computer, find my budget PDF in Downloads."**
   - **"Hey Computer, open Downloads."**
   - **"Hey Claude Code, summarise the repo in Documents."** (needs Claude Code installed on the PC)
3. The result is shown **and spoken back** through the phone's speaker.

Voice works inside the app because it ships a native speech bridge
(Android speech recognition for listening, Android text-to-speech for replies) —
Android's WebView has no built-in Web Speech API. Voice needs:

- the `https://` pairing link (the web app only enables the microphone in a
  secure context — the app handles the certificate),
- a speech-recognition service on the phone (Google's is standard),
- microphone permission for Hey Logan AI.

If a phone has no speech-recognition service, the app still works for typed
commands and shows the app's own message.

## Menu

The three-dot menu has **Reload**, **Change PC** and **About**. Use **Change PC**
when your router gives the PC a new address (run **Pairing** on the PC again).

## Troubleshooting

| Symptom | Fix |
|---|---|
| "Cannot reach the PC" | Is the PC app running? Same Wi-Fi (not a guest network)? Firewall rule added on the PC (**Allow through Firewall**)? Run **Pairing** again to get the current address. |
| Certificate warning / "not private" | Expected: the certificate is generated by your PC. Continue (the app only trusts the paired host). |
| No voice / microphone does nothing | Check *Settings → Apps → Hey Logan AI → Permissions → Microphone*. Also confirm the pairing link started with `https://`. |
| App shows "no speech recognition service" | Install/enable Google speech services, or use typed commands. |
| Pairing link stopped working after a reboot | The PC's IP changed: run **Pairing** on the PC, then **Change PC** in the app. |
| Phone connects but commands do nothing | The PC app must show agents as ready; CLI agents (Claude Code, Codex, …) must be installed on the PC. |

## Prefer not to install an APK?

Open the **pairing link** in Chrome instead, accept the certificate warning
(**Advanced → Proceed**), then Chrome menu → **Add to Home screen**. That gives
you the same UI as an installable web app with full voice support.

## Rebuilding the APK

The source is in `HeyLoganAI-Android-Project-1.0.0.zip` (package
`ai.heylogan.app`, Java, no third-party libraries).

- **Android Studio:** open the folder (the one containing `settings.gradle`),
  let it sync, then *Build → Build App Bundle(s) / APK(s) → Build APK(s)*.
  One gotcha: `AndroidManifest.xml` carries `package="ai.heylogan.app"` because
  the local builds used `aapt2` directly; AGP 8 rejects that attribute and asks
  for `namespace` instead. Delete the `package="…"` attribute from the
  `<manifest>` tag (the namespace already exists in `app/build.gradle`) — the
  bundled CI workflow does exactly that with `sed` before building.
- **Command line (JDK 17 + Android SDK 35):** `gradle assembleRelease`. This
  source tree does not ship the Gradle wrapper JAR; run
  `gradle wrapper --gradle-version 8.9` once if you prefer `gradlew`, or let
  Android Studio create it during sync. The included GitHub Actions workflow
  builds the APK with Gradle when the project folder is pushed as a repository.

The APK shipped here was built with the Android SDK build tools directly
(`aapt2` + `javac` + `d8` + `zipalign` + `apksigner`) because the build machine
could not run Gradle; `android\tools\build-apk-manual.ps1` documents that path.

**Signing:** the release keystore is in `android\release-keystore\`
(`heylogan-release.jks`, alias `heylogan`, password in
`release-keystore\keystore-info.txt`). Keep it — Android only installs updates
signed with the same key. To sign a build yourself:

```
apksigner sign --ks release-keystore\heylogan-release.jks --ks-key-alias heylogan --out app-release-signed.apk app-release-unsigned.apk
```
